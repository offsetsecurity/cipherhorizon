Security

What it touches

  • A scan makes a few hundred short TLS handshakes to its target and, for HTTP services, one GET / read for headers only. It contacts nothing else.
  • The inventory scripts read package lists, certificate files and configuration lines; never private keys. They write a plain-text file readable by its owner only.
  • The server makes no outbound connection except the scans people start, and sends no telemetry.

The server

  • Sign-in is off for one person on their own machine and turned on in Settings for a team; a server on the network will not start open unless told to (--open-network). With sign-in on: administrator, analyst and viewer roles; PBKDF2-SHA256 password hashes; server-side sessions that end after 30 minutes idle or 12 hours, rotated on password change; lock-outs and rate limits.
  • Every sign-in and every change in an append-only activity log, exportable by administrators.
  • HTTPS: TLS 1.2 (forward-secret AEAD) and TLS 1.3 with the hybrid post-quantum key exchange, HSTS, a strict Content Security Policy. Everything a scanned server sends is shown as text, never as markup.
  • Scan scope: --scan-allow; loopback, link-local and cloud-metadata addresses refused by default, checked on the real address of every connection (no DNS rebinding).

Verifying a download

cosign verify-blob checksums.txt --bundle checksums.txt.sigstore.json \
  --certificate-identity-regexp '^https://github.com/OWNER/cipherhorizon/\.github/workflows/release\.yml@refs/tags/v' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
sha256sum --check --ignore-missing checksums.txt
cipherhorizon scripts list         # the inventory scripts' hashes, from the binary

Reporting a vulnerability

Privately, through the repository's security advisories, as SECURITY.md in the source tree describes. Please do not open a public issue.
