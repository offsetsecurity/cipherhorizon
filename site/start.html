Getting started

1. Run it

With Docker or Podman, from the source tree:

docker compose up -d
# then open http://127.0.0.1:8080

Or with a release binary for Linux, macOS or Windows (amd64 and arm64):

cipherhorizon serve                   # http://127.0.0.1:8080; data in your per-user folder

Check the download first: the release's checksums.txt is signed with Sigstore; see Security.

2. Sign-in, when you want it

Sign-in is off, so you can scan straight away. For a team, open Settings and turn it on: that creates the administrator, who adds the other accounts under Users (analysts scan and edit, viewers read and download). To require it from the first start, run serve --sign-in on: the log prints a one-time setup code.

3. Scan an endpoint

Type an address on the Overview and press Enter: example.com, api.example.com:8443, or smtp://mail.example.com for a service that starts with STARTTLS. The report opens with the verdict: the readiness level, the TLS hygiene score and what to fix first. Every check is listed under Weaknesses.

4. Inventory a machine

Under Inventory, take the script for the machine: PowerShell for Windows, shell for Linux. Read it (it is plain text), check its SHA-256, run it, and upload the cipherhorizon-facts-<machine>.txt it writes.

Unblock-File .\cipherhorizon-inventory.ps1; powershell -NoProfile -ExecutionPolicy RemoteSigned -File .\cipherhorizon-inventory.ps1
sudo sh ./cipherhorizon-inventory.sh

The scripts install nothing, change nothing, make no network connection and never read a private key.

5. Try it safely

From the source tree, go run ./cmd/demo-targets starts servers of known posture on 127.0.0.1:9440 and up (start the server with --allow-loopback to scan them). Scan only systems you own or are authorised to test.
