Containers

docker-compose.yml publishes the port on loopback only and runs the container read-only, with no Linux capabilities, no privilege escalation, and bounded processes and memory. The database lives in the data volume.

CIPHERHORIZON_HOST=cipherhorizon.example.com docker compose -f deploy/compose-caddy.yml up -d

With Caddy in front, only Caddy is published; CipherHorizon trusts its network for client addresses, so sign-in limits and the activity log see real clients.

HTTPS without a proxy

cipherhorizon serve --addr 0.0.0.0:8443 --tls-cert cert.pem --tls-key key.pem

TLS 1.2 with forward-secret AEAD suites only, TLS 1.3 with the hybrid post-quantum key exchange, and HSTS. The server passes its own scan.

systemd

sudo install -m 0755 cipherhorizon /usr/local/bin/
sudo install -m 0644 deploy/cipherhorizon.service /etc/systemd/system/
sudo systemctl enable --now cipherhorizon
sudo journalctl -u cipherhorizon          # the log

A dynamic unprivileged user, a private state directory, a read-only system, no capabilities and a system-call filter (systemd-analyze security: 1.5, OK).

Limit what can be scanned

cipherhorizon serve --scan-allow 10.0.0.0/8 --scan-allow example.com

Networks, addresses or domains; checked when an endpoint is added and on every connection. Loopback, link-local and cloud-metadata addresses are refused regardless.

Backups

cipherhorizon db backup --db /var/lib/cipherhorizon/cipherhorizon.db /backup/ch-$(date +%F).db

A consistent copy taken while the server runs, readable by its owner only. To restore, stop the server and put the copy in place of the database. Upgrades keep a copy before migrating; the newest three are kept.
