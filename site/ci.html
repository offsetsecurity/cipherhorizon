CLI and CI

The verdict from the command line

cipherhorizon tls scan example.com
cipherhorizon tls scan --details example.com        # plus every protocol, suite, group and certificate
cipherhorizon tls scan --json example.com           # {target, report, evaluation} per target
cipherhorizon tls scan --cbom example.com           # what was observed, as a CycloneDX CBOM

STARTTLS is chosen by port (25, 587, 143, 110, 21, 5222, 389, 5432), by scheme (smtp://, imap://, ldap://, postgres://...) or with --starttls.

A gate in CI

cipherhorizon tls scan --fail-on 'level<L3,severity>=high' api.example.com www.example.com
ConditionFails when
level<L3Readiness is below level 3 (no hybrid post-quantum key exchange negotiated)
score<70The TLS hygiene score is below 70
severity>=highAny finding of that severity or worse
finding=PROTO.TLS10That finding is present
ExitMeaning
0Scanned, nothing met a condition
1Nothing could be done: bad usage or a bad condition
2A result, but incomplete (without --fail-on)
3A condition was met, or a target could not be scanned at all

GitHub Actions

- name: Scan
  run: ./cipherhorizon tls scan --fail-on 'level<L3,severity>=high' api.example.com:443

Download the release in the job, verify checksums.txt with cosign verify-blob, then run the scan. The full workflow is in docs/CI.md in the source tree. Quote the conditions: < and > are redirections to a shell.

CipherHorizon is open source (Apache 2.0), made by Offset Security. Planning the move to post-quantum cryptography? See Offset's post-quantum readiness practice.
